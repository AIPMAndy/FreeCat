# Mobile purr activation hotfix

User reported no audible purr on tapping a cat. Main source at 662372b92e76c0a66ca6b3be553b4a53ea26dcec starts audio on pointerdown, even for touch, and starts a short preview clock before AudioContext.resume resolves. WebKit describes touch pointerup/touchend as activation events: https://webkit.org/blog/13862/the-user-activation-api/. The exact behavior on the user's device remains unverified.

Changes: initialize cold touch audio on valid pointerup; retry on trusted click; keep mouse and keyboard gestures; start 1.4-second audition only when context is running; invalidate pending audition on mute, blur and stop. Respect persisted mute and canceled gestures. No new audio source, cost, or user data changes.

Verification: 11 mocked checks executed on the actual edited source (cold touch/release, delayed activation, full preview, mute, cancel, mouse, explicit button, stale resume); exact room.html readback matched.
